# URL ownership

Internal URLs belong to one of three layers. Keeping the layers separate is
what allows public page patterns to change without silently breaking links.

## Public pages

Public page URLs are owned by `PageTree` and generated by `UrlGenerator`:

- `action()` for a uniquely named page action;
- `feed()` and `feedTerm()` for content whose route is selected by feed type,
  feed ancestry, or term vocabulary;
- `page()` only when a controller already has the concrete `Page` being
  rendered.

Twig resolves action-owned page links with `action_url()`. Controllers pass
contextual page, feed, and term URLs to templates when the target depends on
the object being rendered. Fixed transport endpoints and resource paths remain
explicit at their point of use instead of being proxied through view data.

The site root `/`, administration entry point `/admin/`, and installer-only
`/install` endpoint are fixed application entry points.

## Versioned API

`/api/v1` is a stable transport contract, not a public page permalink. PHP
and TypeScript keep these endpoints explicit in the code. Dynamic string
segments must be encoded with `rawurlencode()` in PHP or
`encodeURIComponent()` in TypeScript. URLs already supplied by the server
through form actions or data attributes are consumed as-is by the client.

API endpoints must not be generated through `UrlGenerator`: changing a public
page pattern must not rename an API.

## Assets and stored files

`/assets`, favicon paths, and stored `/uploads` paths are resource URLs rather
than router pages. They stay outside both page and API URL generators.
